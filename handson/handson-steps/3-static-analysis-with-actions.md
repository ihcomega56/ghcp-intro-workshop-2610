## この章でやること

GitHub Actions を使い、PR を作成したときや main ブランチに push したときに、Python の静的解析が自動で実行されるようにします。

このハンズオンでは、安全のため次のルールでワークフローを作ります。

- 使うアクションは GitHub 公式（`actions/` で始まるもの）だけにする
- 静的解析ツールは OSS の [Ruff](https://docs.astral.sh/ruff/) を使い、`pip` でインストールする
- アクションのバージョンは、タグ（`v7` など）ではなくコミット SHA（40文字の英数字）で固定する

## 手順

### ワークフローを作成する

1. 第2章と同じように、Copilot Chat（**Agent**）に作業用のブランチを作ってもらいます。
1. 次のプロンプトを送信します。

    ```text
    GitHub Actions で Python の静的解析を行うワークフローを作成してください。

    - main ブランチへの push と、main ブランチ向けの Pull Request で実行する
    - 使ってよいアクションは GitHub 公式（actions/ で始まるもの）のみとし、サードパーティのアクションは使わない
    - アクションはタグではなくフルのコミット SHA で指定し、行末にコメントでバージョンを書く
    - SHA は推測せず、git ls-remote などで実際に取得した値を使う
    - 静的解析ツールは Ruff を pip でインストールして実行する
    - ワークフローの権限は contents: read のみにする
    - ローカルでも同じチェックを実行できるよう、手順を README に追記する
    ```

1. Copilot が `git ls-remote` などのコマンドで SHA を取得しようとしたら、コマンドを確認してから許可します。
1. 作成された `.github/workflows/` 配下の YAML ファイルを開き、次を確認します。
    - `uses:` の行が `actions/checkout@<40文字の英数字> # v7.0.1` のような形になっている
    - `actions/` 以外のアクションが使われていない
    - `permissions:` に `contents: read` が指定されている
1. SHA が正しいかをブラウザーで確認します。
    1. `https://github.com/actions/checkout/releases` を開きます。
    1. YAML のコメントに書かれたバージョン（例: `v7.0.1`）のリリースを探し、コミット SHA の短縮表記（7文字程度）をクリックします。
    1. 表示されたコミットの SHA が、YAML に書かれた SHA と一致することを確認します。
    1. `actions/setup-python` など、ほかのアクションも同じように確認します。

### ローカルで静的解析を実行する

1. ターミナルで仮想環境が有効になっていることを確認します（プロンプトの先頭に `(.venv)` と表示されます）。有効になっていない場合は、第2章と同じコマンドで有効化します。
1. README に追記された手順に従い、ターミナルで Ruff をインストールして実行します。通常は次のコマンドです。

    ```sh
    pip install ruff
    ruff check .
    ```

1. 指摘が表示された場合は、Copilot Chat に次のプロンプトを送信し、修正してもらいます。

    ```text
    #terminalLastCommand Ruff の指摘内容を説明し、修正してください。修正後にもう一度 ruff check を実行して確認してください。
    ```

1. `All checks passed!` と表示されることを確認します。

### PR を作成し、Actions の実行を確認する

1. 第2章と同じように、Copilot にコミット、push、PR の作成を依頼し、返ってきた PR の URL をブラウザーで開きます。
1. PR の下部にあるチェックの欄に、作成したワークフローが表示され、実行中（黄色の丸）になっていることを確認します。
1. **Details** をクリックして、ワークフローのログを確認します。`ruff check` が実行されていることを確認します。
1. 緑色のチェックマークになったら、第2章と同じようにマージし、ローカルを最新の状態にします。
1. リポジトリの **Actions** タブを開き、main ブランチへの push でもワークフローが実行されたことを確認します。

## プロンプト例

- GitHub Actions のアクションを、タグではなくコミット SHA で固定する理由を説明してください。
- このワークフローの YAML を1行ずつ説明してください。
- `permissions: contents: read` を指定すると何が変わりますか？
- Ruff とは何ですか？flake8 などのほかのツールとの違いを教えてください。
- このワークフローが失敗したときに、どこを見れば原因が分かりますか？

## 余裕がある方向けの追加ワーク

1. わざと Ruff に指摘されるコード（使っていない `import` など）を追加した PR を Copilot に作ってもらい、Actions のチェックが失敗（赤い×）になることを確認します。確認できたら、その PR は **Close pull request** で閉じます。
1. Ruff の設定（チェックするルールの種類など）を設定ファイルにまとめるよう、Copilot に相談します。
1. リポジトリの **Settings → Actions → General** を開き、許可するアクションを GitHub 公式などに制限する設定や、アクションを SHA で固定することを必須にする設定があることを確認します。
