## この章でやること

第4章で作成した Issue を実装し、PR を送ります。PR には Copilot をレビュアーとしてアサインし、Copilot のレビューと GitHub Actions のチェックの結果を確認してから、チームでマージします。

作業の進め方は、次のどちらでもかまいません。

- 個人: メンバーがそれぞれ別の Issue を担当し、並行して実装する
- ペアプロ・モブプロ: 1人が画面を共有して操作し、ほかのメンバーはプロンプトや確認観点を提案しながら、全員で1つの Issue を実装する

## 手順

### 担当する Issue を決める

1. チームで、誰がどの Issue を担当するかを決めます。
1. ブラウザーで担当する Issue を開き、右側の **Assignees** で **assign yourself** をクリックして、自分を担当者にします。
1. Issue の番号（例: `#3`）を控えます。

### Issue の内容から作業用のブランチを作る

1. VS Code でチームのリポジトリを開き、Copilot Chat のエージェントを **Agent** にします。
1. 次のプロンプトを送信します。`#3` は担当する Issue の番号に置き換えます。

    ```text
    このリポジトリの Issue #3 に取り組みます。Issue の内容を読んで要約してください。その後、main ブランチを最新にしてから、Issue 番号を含む作業用ブランチを作成して切り替えてください。
    ```

1. 実行されるコマンドやツールを確認してから許可します。
1. Copilot が Issue を読めなかった場合は、ブラウザーで Issue の本文をコピーし、チャットに貼り付けて依頼し直します。

### Plan で計画を立て、Agent で実装する

1. **Plan** で計画を立ててから **Agent** で実装します。プロンプトの例: `Issue #3 の完了条件をすべて満たすための実装計画を立ててください。` -> `計画の通り実装し、Pull Requestを作成してください。`
1. ペアプロ・モブプロの場合は、計画と差分をチームで確認します。
1. アプリの動作と `ruff check .` の結果を確認します。

### PR を作成する

1. Copilot に、第2章と同じようにコミット、push、PR の作成を依頼します。このとき、`PR の説明の最後に「Closes #3」を入れてください。` と付け加えます。`Closes #3` があると、PR のマージ時に Issue が自動で閉じられます。
1. Copilot が返した PR の URL をブラウザーで開きます。

### Copilot にレビューを依頼し、Actions のチェックを確認する

1. ブラウザーで PR を開き、右側の **Reviewers** の歯車アイコンをクリックし、**Copilot** を選択します。**Copilot** の横に **Request** が表示されている場合は、それをクリックします。
1. PR の下部のチェックの欄に、第3章で作成した静的解析のワークフローが表示され、実行されていることを確認します。
1. 数分待つと、Copilot からレビューコメントが届きます。**Files changed** タブまたは **Conversation** タブでコメントを読みます。
1. 指摘への対応方法を選びます。
    - 修正案（suggestion）付きのコメントで、そのまま採用してよい場合: **Commit suggestion** をクリックします。
    - VS Code で修正する場合: Copilot Chat に `この PR についた Copilot のレビューコメントを確認し、対応が必要なものを修正してコミット、push してください。` と依頼します。読み込めない場合は、コメントをコピーしてチャットに貼り付けます。
    - 対応不要と判断した場合: その理由をコメントで返信し、**Resolve conversation** をクリックします。
1. 修正を push すると、Actions のチェックがもう一度実行されることを確認します。
1. Actions のチェックが失敗（赤い×）した場合は、**Details** からログを開いてエラー部分をコピーし、Copilot Chat に貼り付けて原因と修正を依頼します。

### チームでレビューし、マージする

1. チームのほかのメンバーに PR の URL を共有し、レビューを依頼します。
1. レビューする人は、PR の **Files changed** タブで変更内容を確認します。気になる行にはその行の **＋** をクリックしてコメントを書きます。
1. 問題がなければ、レビューする人は **Review changes** をクリックし、**Approve** を選んで **Submit review** をクリックします。
1. PR の作成者は、Actions のチェックが緑色であること、レビューが Approve されていることを確認し、第2章と同じようにマージします。
1. Issue を開き、自動で **Closed** になっていることを確認します。
1. すべての PR のマージが終わったら、全員がローカルを最新の状態にし、アプリを起動してチーム全員の変更が反映されていることを確認します。

## プロンプト例

- この PR の変更内容を、レビューする人向けに3行で要約してください。
- `#changes` コミットする前に、この変更をレビューしてください。バグになりそうな点やテストが足りない点を指摘してください。
- Copilot のレビューコメントで指摘された内容が妥当かどうか、理由とともに説明してください。
- Actions のログに表示された次のエラーの原因を教えてください。（ログを貼り付ける）
- この Issue の完了条件を、今の実装がすべて満たしているか確認してください。

## 余裕がある方向けの追加ワーク

1. 残っている Issue をブラウザーで開き、右側の **Assignees** で **Copilot** を選択して、Copilot cloud agent に実装を任せます。作成された PR をチームでレビューし、マージします。
1. PR のレビューコメントで、Copilot のコメントにある **Fix with Copilot** を試し、cloud agent に修正を任せます。
1. VS Code のソース管理ビューや Copilot Chat で、コミット前の変更を Copilot にレビューさせ、PR を作る前に問題を見つけます。
