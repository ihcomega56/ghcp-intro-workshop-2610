## この章でやること

ここからはチームで作業します。チームで使うリポジトリを1つ決め、メンバーを招待します。招待されたメンバーはリポジトリを clone し、自分が作ったものとは違うアプリを実行したり、Copilot に解析させたりします。その後、どんな機能を追加できるかをチームで相談し、Copilot を使って Issue を作成します。

## 手順

### チームとリポジトリを決める

1. 講師の案内に従い、3〜4人のチームを組みます。
1. 各自が第2章・第3章で作ったアプリを画面共有などで簡単に紹介し合います。
1. チームで使うリポジトリを1つ決めます。このリポジトリの持ち主を、以降「オーナー」と呼びます。
1. オーナーのリポジトリの URL（`https://github.com/<オーナーのユーザー名>/<リポジトリ名>`）をチームで共有します。

### メンバーを招待する（オーナーのみ）

1. ブラウザーでリポジトリを開き、**Settings** タブをクリックします。
1. 左側のメニューで **Collaborators**（Organization のリポジトリの場合は **Collaborators and teams**）をクリックします。認証を求められた場合は、画面の指示に従います。
1. **Add people** をクリックし、メンバーの GitHub ユーザー名を入力して選択し、**Add ... to this repository** をクリックします。Organization のリポジトリの場合は、ロールに **Write** を選択します。
1. ほかのメンバーも同じように招待します。

### 招待を承諾する（メンバーのみ）

1. GitHub から届いた招待メールの **View invitation** をクリックするか、ブラウザーで `https://github.com/<オーナーのユーザー名>/<リポジトリ名>/invitations` を開きます。
1. **Accept invitation** をクリックします。
1. リポジトリのページが表示されることを確認します。

### チームのリポジトリを clone して実行する（メンバーのみ）

1. ブラウザーでチームのリポジトリを開き、緑色の **Code** ボタンから HTTPS の URL をコピーします。
1. VS Code で **ファイル → 新しいウィンドウ** を開き、**ターミナル → 新しいターミナル** でターミナルを開きます。
1. ターミナルで次のコマンドを入力します。URL はコピーしたものに置き換えます。自分のリポジトリと同じ名前の場合は、最後にフォルダー名（例: `team-app`）を指定して、別のフォルダーに clone します。

    ```sh
    cd ~
    git clone https://github.com/<オーナーのユーザー名>/<リポジトリ名>.git team-app
    ```

1. **ファイル → フォルダーを開く** で、clone したフォルダー（`~/team-app`）を開きます。
1. 新しいターミナルを開き、`git config user.name` と `git config user.email` で、コミットに使う名前とメールアドレスが設定されているか確認します。何も表示されない場合は、第1章と同じ手順で設定します。
1. README の手順に従い、仮想環境を作成してアプリを起動します。うまくいかない場合は、第2章と同じように `#terminalLastCommand` を付けて Copilot に質問します。
1. ブラウザーでアプリを操作し、自分が作ったアプリとの違いを確認します。

### Copilot にアプリを解析させる（全員）

1. Copilot Chat を開き、エージェントを **Ask** にします。
1. 次のプロンプトを送信し、アプリの構成を把握します。

    ```text
    #codebase このアプリのファイル構成と、各ファイルの役割を表にまとめてください。また、画面の操作からデータが保存・表示されるまでの処理の流れを Mermaid のフロー図で示してください。
    ```

1. 気になった部分について質問を続けます。
    - このアプリで、テストが書かれている部分と書かれていない部分を教えてください。
    - README の手順に、初めての人がつまずきそうな点はありますか？
1. オーナーは、ほかのメンバーが見つけた疑問点や気づきを聞き、チームで共有します。

### 追加する機能を相談し、Issue を作成する（全員）

1. Copilot Chat に次のプロンプトを送信し、機能のアイデアを出してもらいます。

    ```text
    #codebase このアプリに追加すると便利な機能や、改善すべき点を5つ提案してください。それぞれ、作業の大きさ（小・中・大）と、変更が必要になりそうなファイルも示してください。
    ```

1. Copilot の提案と自分たちのアイデアをもとに、チームで追加する機能を相談し、メンバーの人数分程度の Issue にすることを決めます。1つの Issue は、30分程度で実装できる大きさにします。
1. 各メンバーが1つずつ、Copilot Chat のエージェントを **Agent** にして、次のようなプロンプトで Issue を作成します。

    ```text
    このリポジトリに、次の内容で GitHub Issue を作成してください。
    本文には「背景」「やりたいこと」「完了条件」の見出しを入れ、完了条件はチェックリストにしてください。

    タイトル: 注文時にテイクアウトかイートインかを選べるようにする
    内容: 注文確定前にテイクアウト/イートインを選択でき、注文履歴にも記録されるようにしたい
    ```

1. Copilot が Issue を作成するためのツールの実行許可を求めてきたら、内容（作成先のリポジトリ、タイトル、本文）を確認してから許可します。
1. ブラウザーでリポジトリの **Issues** タブを開き、Issue が作成されていることを確認します。
1. Copilot から「Issue を作成するツールがない」などと返ってきた場合は、Copilot が書いた本文をコピーし、ブラウザーの **Issues** タブで **New issue** をクリックして作成します。
1. 同じ Issue が重複して作成されていないか、チームで確認します。

## プロンプト例

- `#codebase` このアプリと、一般的な Streamlit アプリの構成の違いを教えてください。
- `#codebase` このアプリのコードで、読みにくい部分やバグになりそうな部分はありますか？
- 作成した Issue の完了条件が十分に具体的か、レビューしてください。
- この Issue を実装する場合、どのファイルをどのように変更すればよいか、作業手順を示してください。
- このリポジトリの Open な Issue を一覧にしてください。

## 余裕がある方向けの追加ワーク

1. ブラウザーで Issue を開き、**Labels** から `enhancement` などのラベルを付けます。Copilot に「Issue にラベルを付けて」と依頼してもかまいません。
1. 大きな Issue を、Copilot に依頼して小さなサブ Issue に分割します。
1. github.com の画面右上にある Copilot アイコンからチャットを開き、リポジトリについて質問したり、Issue の下書きを作成したりします。
