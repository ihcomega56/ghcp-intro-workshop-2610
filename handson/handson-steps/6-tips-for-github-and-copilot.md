## この章でやること

GitHub と GitHub Copilot をチームでもっと使いこなすための仕組みを試します。興味のあるものから自由に選んで取り組んでください。チームで分担して取り組み、最後に何を作ったかを共有するのもおすすめです。

リポジトリに追加するファイルは、第2章と同じように **作業用ブランチ → PR → レビュー → マージ** の流れで反映します。

| Tips | 作るもの | 何がうれしいか |
| ---- | ---- | ---- |
| A | `.github/copilot-instructions.md` | プロジェクトのルールを毎回プロンプトに書かなくて済む |
| B | `.github/instructions/*.instructions.md` | 特定のファイルにだけ適用するルールを書ける |
| C | `AGENTS.md` | Copilot 以外の AI エージェントとも共通の指示を共有できる |
| D | `.github/prompts/*.prompt.md` | よく使うプロンプトをスラッシュコマンドとして呼び出せる |
| E | `.github/agents/*.agent.md` | レビュー専用など、役割を持ったエージェントを作れる |
| F | `.github/skills/*/SKILL.md` | 手順やスクリプトをまとめた「能力」を Copilot に持たせられる |
| G | `.github/CODEOWNERS` とルールセット | 変更内容に応じてレビュアーを自動で割り当て、マージの条件を決められる |
| H | PR テンプレート、Issue テンプレート | PR や Issue に書く内容をそろえられる |
| I | `.github/dependabot.yml` | 依存パッケージやアクションの SHA を自動で最新に保てる |

## 手順

### A. カスタムインストラクションを作る

リポジトリ全体に適用されるルールを書いておくと、Copilot Chat、cloud agent、Copilot code review がそのルールに従います。

1. Copilot Chat の入力欄に `/init` と入力して送信します。Copilot がリポジトリを解析し、`.github/copilot-instructions.md` を作成します。
1. `/init` が候補に表示されない場合は、次のプロンプトで依頼します。

    ```text
    #codebase このリポジトリのカスタムインストラクションを .github/copilot-instructions.md に作成してください。プロジェクトの概要、使っている技術、アプリの起動方法、静的解析とテストのコマンド、コーディングのルールを含めてください。回答やコミットメッセージは日本語で書くというルールも入れてください。
    ```

1. 作成されたファイルを開き、内容が正しいか確認します。チームで決めたいルール（例: 「関数には型ヒントを付ける」「画面の文言は日本語にする」）があれば追記します。
1. **＋**（新しいチャット）でチャットを開き直し、`#codebase このアプリに新しい画面を追加する場合の手順を教えてください。` と送信します。回答の下にある **参照** に `copilot-instructions.md` が含まれていることを確認します。

### B. 特定のファイルにだけ適用するインストラクションを作る

1. 次のプロンプトを送信します。

    ```text
    テストコードを書くときのルールを .github/instructions/tests.instructions.md に作成してください。applyTo でテストファイルだけに適用されるようにし、pytest を使うこと、テスト名は日本語で何を確認しているか分かるようにすることを書いてください。
    ```

1. 作成されたファイルの先頭にある `applyTo:` の値を確認し、どのファイルに適用されるかを Copilot に説明してもらいます。

### C. AGENTS.md を作る

1. 次のプロンプトを送信します。

    ```text
    リポジトリのルートに AGENTS.md を作成してください。AI エージェントがこのリポジトリで作業するときに必要な情報（セットアップ方法、起動方法、静的解析とテストのコマンド、ブランチと PR のルール）を簡潔にまとめてください。
    ```

1. `copilot-instructions.md` と `AGENTS.md` の使い分けを、Copilot に質問してみます。

### D. プロンプトファイルでスラッシュコマンドを作る

1. 次のプロンプトを送信します。

    ```text
    .github/prompts/add-menu-item.prompt.md というプロンプトファイルを作成してください。
    実行すると、商品名・価格・カテゴリをユーザーに質問し、その内容でメニューに商品を追加して、アプリの静的解析とテストを実行するようにしてください。
    ```

1. **＋**（新しいチャット）でチャットを開き直し、入力欄に `/add-menu-item` と入力して送信します。
1. Copilot がプロンプトファイルの内容に従って動作することを確認します。

### E. カスタムエージェントを作る

1. 次のプロンプトを送信します。`/create-agent` が候補に表示される場合は、`/create-agent` に続けて同じ内容を書いてもかまいません。

    ```text
    .github/agents/reviewer.agent.md というカスタムエージェントを作成してください。
    コードの変更をレビューする専用のエージェントで、ファイルの編集やコマンドの実行は行わず、読み取りと検索だけを行います。
    バグ、セキュリティ、テスト不足、読みやすさの観点で指摘し、重要度を「高・中・低」で示してください。
    ```

1. チャットのエージェントの選択メニューを開き、作成した **reviewer** が表示されることを確認します。
1. **reviewer** を選び、`#changes 今の変更をレビューしてください。` と送信します。

### F. スキルを作る

1. 次のプロンプトを送信します。`/create-skill` が候補に表示される場合は、`/create-skill` に続けて同じ内容を書いてもかまいません。

    ```text
    .github/skills/run-checks/SKILL.md というスキルを作成してください。
    コードを変更したあとに、仮想環境を確認し、Ruff による静的解析と pytest によるテストを実行して、成功・失敗・未実行の項目を報告するスキルです。
    いつこのスキルを使うべきかを frontmatter の description に書いてください。
    ```

1. **＋**（新しいチャット）でチャットを開き直し、`/run-checks` と送信するか、`変更内容をチェックしてください` と依頼して、スキルが使われることを確認します。

### G. CODEOWNERS とルールセットでレビューのルールを決める

1. 次のプロンプトを送信します。

    ```text
    .github/CODEOWNERS を作成してください。.github/ 配下のファイルは <オーナーのユーザー名> を、それ以外のすべてのファイルはチームメンバー全員（<ユーザー名1> <ユーザー名2> <ユーザー名3>）をコードオーナーにしてください。
    ```

1. 作成されたファイルの内容を確認し、PR を作成してマージします。
1. 以降、新しい PR を作成すると、**Reviewers** にコードオーナーが自動で追加されることを確認します。
1. オーナーは、ブラウザーでリポジトリの **Settings → Rules → Rulesets** を開き、**New ruleset → New branch ruleset** をクリックします。
1. 次のとおり設定し、**Create** をクリックします。
    - **Ruleset Name**: `main`
    - **Enforcement status**: **Active**
    - **Target branches**: **Add target → Include default branch**
    - **Require a pull request before merging** にチェックを入れ、**Required approvals** を `1` にし、**Require review from Code Owners** にチェックを入れる
    - **Automatically request Copilot code review** にチェックを入れる
    - **Require status checks to pass** にチェックを入れ、**Add checks** から第3章で作成した静的解析のジョブを追加する
1. 新しく PR を作成し、Copilot のレビューが自動で依頼されること、Approve とチェックの成功がないとマージできないことを確認します。

private リポジトリでルールセットを使うには、GitHub Pro、GitHub Team などの有料プランが必要です。ルールセットの画面が使えない場合は、CODEOWNERS による自動のレビュアー割り当てだけを確認してください。

### H. PR テンプレートと Issue テンプレートを作る

1. 次のプロンプトを送信します。

    ```text
    .github/pull_request_template.md に PR テンプレートを作成してください。「概要」「関連 Issue」「変更内容」「動作確認」「レビューしてほしい点」の見出しを入れてください。
    また、.github/ISSUE_TEMPLATE/ に、機能追加用とバグ報告用の Issue フォームを YAML で作成してください。
    ```

1. マージ後、ブラウザーで **Issues → New issue** をクリックし、テンプレートを選べるようになっていることを確認します。

### I. Dependabot で依存関係を最新に保つ

1. 次のプロンプトを送信します。

    ```text
    .github/dependabot.yml を作成し、GitHub Actions のアクションと pip のパッケージを週に1回チェックするように設定してください。
    ```

1. マージ後、ブラウザーで **Insights → Dependency graph → Dependabot** を開き、設定が読み込まれていることを確認します。アクションを SHA で固定していても、Dependabot が新しいバージョンの SHA に更新する PR を作成してくれます。

## プロンプト例

- カスタムインストラクション、プロンプトファイル、カスタムエージェント、スキルの違いと使い分けを表にしてください。
- `#codebase` このリポジトリのカスタムインストラクションに追記したほうがよいルールを提案してください。
- CODEOWNERS とルールセットを組み合わせると、どのようなことができますか？
- Copilot code review の指摘をチームのルールに合わせるには、どうすればよいですか？
- このリポジトリで、ほかに自動化できそうな作業はありますか？

## 余裕がある方向けの追加ワーク

1. `Ctrl + Shift + P`（macOS は `⌘ + ⇧ + P`）でコマンドパレットを開き、**Chat: Open Customizations** を実行して、作成したカスタマイズの一覧を確認します。
1. 次の機能も調べて、試してみます。
    - GitHub Copilot CLI: ターミナルから Copilot に作業を依頼する
    - MCP サーバー: Copilot から外部のツールやサービスを使えるようにする
    - Copilot のメモリー: 会話をまたいで覚えておいてほしいことを Copilot に記憶させる
    - フック: Copilot の作業の特定のタイミングで、決まったコマンドを必ず実行させる
    - Secret scanning の push protection: パスワードやトークンを誤って push するのを防ぐ
1. 個人のリポジトリに戻り、ここで作ったカスタマイズを自分のリポジトリにも取り入れます。

## ふりかえり

1. チームごとに、作ったアプリと、追加したカスタマイズを1〜2分で共有します。
1. Copilot に任せてうまくいったこと、うまくいかなかったことを話し合います。
1. Copilot の提案を採用する前に、どのような観点で確認すべきかをチームでまとめます。
