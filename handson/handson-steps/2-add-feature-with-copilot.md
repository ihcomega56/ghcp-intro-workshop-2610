## この章でやること

ここからは VS Code の GitHub Copilot を使います。まず Copilot Chat の基本操作として、スラッシュコマンドと `#` によるコンテキスト指定を練習し、アプリの解析やターミナルのエラー解析を Copilot に任せてみます。その後、自分のリポジトリに機能追加やデザイン変更の PR を送り、マージします。

この章以降、Git の操作（ブランチ作成、コミット、push、PR 作成など）は Copilot に依頼して行います。

## 手順

### Copilot Chat を開き、モードを確認する

1. 第1章で clone したリポジトリを VS Code で開きます。
1. 画面上部の Copilot アイコンをクリックするか、`Ctrl + Alt + I`（macOS は `⌃ + ⌘ + I`）を押して Copilot Chat を開きます。
1. チャット入力欄の下にあるエージェントの選択メニューを開き、**Ask**、**Plan**、**Agent** が選べることを確認します。
    - Ask: 質問や調査だけを行い、ファイルを変更しない
    - Plan: 変更前に、作業手順や変更するファイルを計画する
    - Agent: ファイルの編集やコマンドの実行まで行う
1. 同じ場所にあるモデルの選択メニューを開き、選べるモデルを確認します。迷ったら **Auto** のままで問題ありません。

### スラッシュコマンドを使ってみる

1. エージェントを **Ask** にします。
1. チャット入力欄に `/` を入力し、表示される候補を確認します。
1. エディターで `app.py` を開き、関数やループなど数行を選択します。
1. チャット入力欄に次のように入力して送信します。

    ```text
    /explain
    ```

1. 選択した部分の説明が返ってくることを確認します。
1. チャット入力欄の上部にある **＋**（新しいチャット）をクリックするか、`/clear` を送信して、新しいチャットを始めます。話題を変えるときは、新しいチャットにすると回答の精度が上がります。

### `#` でコンテキストを与える

1. チャット入力欄に `#` を入力し、表示される候補（ファイル、ツールなど）を確認します。
1. 次のプロンプトを送信して、アプリ全体を解析させます。`#codebase` は、`#` を入力した後に候補から `codebase` を選んでも入力できます。

    ```text
    #codebase このアプリはどんなアプリですか？ファイル構成と主な処理の流れを、初心者向けに説明してください。
    ```

### ターミナルの情報を Copilot に解析させる

1. メニューの **ターミナル → 新しいターミナル** でターミナルを開きます。
1. ターミナルに次のコマンドを入力し、あえて README の手順を無視してアプリを実行します。

    ```sh
    # Windows
    python app.py

    # macOS
    python3 app.py
    ```

1. `ModuleNotFoundError` などのエラーや警告が表示されることを確認します。
1. Copilot Chat に次のプロンプトを送信します。`#terminalLastCommand` で、直前にターミナルで実行したコマンドとその出力を Copilot に渡せます。

    ```text
    #terminalLastCommand このエラーの原因と、正しい起動方法を教えてください。
    ```

1. 回答に「仮想環境」が出てきたら、続けて次の質問を送信します。

    ```text
    Python の仮想環境（venv）とは何ですか？なぜ使うのですか？仮想環境を使わずに pip install した場合との違いも、初心者向けに説明してください。
    ```

1. ターミナルで次のコマンドを順に実行し、仮想環境を作ってアプリを起動します。

    ```powershell
    # Windows（PowerShell）
    python -m venv .venv
    .venv\Scripts\Activate.ps1
    pip install -r requirements.txt
    streamlit run app.py
    ```

    ```sh
    # macOS
    python3 -m venv .venv
    source .venv/bin/activate
    pip install -r requirements.txt
    streamlit run app.py
    ```

1. 途中でエラーになった場合は、もう一度 `#terminalLastCommand` を付けて Copilot に原因を聞きます。たとえば Windows で `Activate.ps1` の実行が拒否された場合、その理由と対処方法を説明してもらいます。
1. ブラウザーで `http://localhost:8501` が開き、アプリが表示されることを確認します。
1. 「Python インタープリターを選択してください」などの通知が VS Code に表示された場合は、`.venv` の Python を選択します。
1. 確認できたら、ターミナルで `Ctrl + C` を押してアプリを停止します。

### 作業用のブランチを Copilot に作ってもらう

1. エージェントを **Agent** に切り替えます。
1. 次のプロンプトを送信します。

    ```text
    main ブランチを最新にしてから、これから行う機能追加のための作業用ブランチを作成して切り替えてください。ブランチ名は内容が分かる英語にしてください。
    ```

1. Copilot がターミナルでコマンドを実行しようとすると、確認が表示されます。表示されたコマンド（`git switch`、`git pull` など）を読み、問題なければ **許可**（**Allow**）をクリックします。
1. VS Code の左下（ステータスバー）に表示されるブランチ名が変わったことを確認します。

### Plan で計画を立て、Agent で実装する

1. エージェントを **Plan** に切り替えます。
1. 下の「機能追加のサンプルプロンプト」から1つ選ぶか、自分で考えた機能追加やデザイン変更の内容を送信します。
1. Copilot が提示した計画を読み、次を確認します。
    - どのファイルを作成・変更する予定か
    - 追加するパッケージがあるか
    - 動作確認の方法
1. 気になる点があれば、Plan のまま「〇〇は不要です」「△△も追加してください」のように修正を依頼します。
1. 計画に納得したら、エージェントを **Agent** に切り替え、`この計画で実装してください。実装後にアプリが起動することも確認してください。` と送信します。計画の下に実装を開始するボタンが表示された場合は、それをクリックしてもかまいません。
1. Copilot がコマンドの実行許可を求めてきたら、内容を確認してから許可します。
1. 実装が終わったら、チャットに表示された変更ファイルの一覧から各ファイルを開き、差分を確認します。問題なければ **保持**（**Keep**）、取り消したい場合は **元に戻す**（**Undo**）をクリックします。
1. ターミナルで `streamlit run app.py`（起動ファイルが変わった場合は README に書かれたコマンド）を実行し、ブラウザーで動作を確認します。期待どおりでなければ、チャットで修正を依頼します。

#### 機能追加のサンプルプロンプト

何を追加するか思いつかない場合は、次のいずれかを使ってください。

1. 注文履歴と売上ダッシュボード

    ```text
    注文を確定したら、その内容（日時、商品、数量、金額）を記録し、あとから見返せるようにしたいです。
    - 外部サービスは使わず、ローカルに保存してください
    - アプリを再起動しても履歴が残るようにしてください
    - 注文画面とは別に「売上ダッシュボード」画面を用意し、サイドバーから切り替えられるようにしてください
    - ダッシュボードでは、商品別の販売数と合計売上をグラフで表示してください
    - README の内容も変更に合わせて更新してください
    ```

1. メニューのカテゴリ化とセット割引

    ```text
    メニューを増やし、運用しやすくしたいです。
    - 店員がプログラムを読まなくてもメニューの追加や価格変更ができるよう、商品データはプログラムとは分けて管理してください
    - 商品に「ドリンク」「フード」「デザート」のカテゴリを持たせ、カテゴリごとにタブで表示してください
    - ドリンクとデザートを同時に注文すると 100 円引きになるセット割引を入れてください
    - 割引の計算が正しいことを確認できる自動テストを pytest で書き、実行して結果を確認してください
    - README の内容も変更に合わせて更新してください
    ```

1. カフェらしいデザインへの変更

    ```text
    アプリの見た目をカフェらしく整えたいです。
    - 全体の配色をブラウン系にし、アプリを起動し直しても同じ配色が適用されるようにしてください
    - 商品をカード形式で並べ、商品ごとに絵文字のアイコンを表示してください
    - スマートフォンの画面幅でも崩れないレイアウトにしてください
    - ヘッダーに店名とキャッチコピーを表示し、店名はコードを書き換えずに設定で変更できるようにしてください
    - README の内容も変更に合わせて更新してください
    ```

### コミット、push、PR の作成を Copilot に依頼する

1. Agent のまま、次のプロンプトを送信します。

    ```text
    #changes 今回の変更内容を確認し、内容が分かる日本語のコミットメッセージでコミットして、リモートに push してください。.venv などコミットすべきでないファイルが含まれていないかも確認してください。
    ```

1. 実行されるコマンド（`git add`、`git commit`、`git push` など）を確認してから許可します。
1. 続けて次のプロンプトを送信します。

    ```text
    このブランチから main ブランチへの Pull Request を作成してください。タイトルと説明は変更内容をもとに日本語で書き、説明には動作確認の方法も含めてください。
    ```

1. Copilot が PR の URL を返したら、クリックしてブラウザーで開きます。
1. Copilot から「GitHub を操作するツールがない」などと返ってきた場合は、ブラウザーでリポジトリを開き、表示される **Compare & pull request** をクリックして PR を作成します。説明欄の Copilot アイコンから、説明文を自動生成することもできます。

### ブラウザーで PR を確認してマージする

1. ブラウザーで PR を開き、**Files changed** タブで変更内容を確認します。
1. **Conversation** タブに戻り、**Squash and merge** をクリックし、続けて **Confirm squash and merge** をクリックします。
1. **Delete branch** をクリックします。
1. VS Code に戻り、Copilot に次のプロンプトを送信して、ローカルを最新の状態にします。

    ```text
    main ブランチに切り替えて最新の状態を取得し、マージ済みのローカルブランチを削除してください。
    ```

## プロンプト例

- `#codebase` このアプリで、メニューの価格を変更したい場合はどのファイルのどこを直せばよいですか？
- `#terminalLastCommand` このエラーメッセージを初心者向けに説明してください。
- `#selection` この処理をもっと読みやすくするには、どう書き換えられますか？（エディターでコードを選択してから送信）
- `/explain` Streamlit の `st.session_state` は何のために使われていますか？
- `requirements.txt` と仮想環境の関係を説明してください。
- 今のブランチと main ブランチの違いを教えてください。
- 直前のコミットで何を変更したか、要約してください。

## 余裕がある方向けの追加ワーク

1. 残りのサンプルプロンプトにも取り組み、同じ手順で2つ目の PR を送ってマージします。
1. エディターで新しい関数を書き始め、灰色で表示されるコードの提案（インライン提案）を `Tab` で採用します。
1. エディターでコードを選択して `Ctrl + I`（macOS は `⌘ + I`）を押し、インラインチャットで「この部分にコメントを追加して」と依頼します。
1. VS Code の **ソース管理** ビューで、コミットメッセージ欄の横にある Copilot（きらめき）アイコンをクリックし、コミットメッセージが自動生成されることを確認します。
